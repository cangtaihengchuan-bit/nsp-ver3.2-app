# 価格インテリジェンス実装工程表

最終更新: 2026-07-12

## 方針

Kaimono Clockの中心体験は「買う前の確認」と「買った後の記録」のままとする。価格インテリジェンスは、十分な観測数・同意率・協力店舗・継続費用が揃うまで一般ユーザーへ公開しない。

- 全国最安値ではなく、特定地域・カテゴリの「参考価格」から始める。
- 自動登録より、短時間で確認・修正できる半自動処理を優先する。
- 家計簿データは本人の生活費管理、価格観測は明示同意した相場分析という別目的で扱う。
- SNS・チラシサイトを無断取得しない。店舗許可済みAPI、OAuth、手動登録だけを対象にする。
- 本番DBに先行して空テーブルを追加しない。

## 第1段階: 今できること

### 1A. 設計と検証環境

- [x] 出典種別、証跡、OCR、生データ、確認済みデータを分離する。
- [x] 店舗企業・支店・商品・別名・価格観測の識別方針を定義する。
- [x] ER図、カラム候補、RLS、保持期間を定義する。
- [x] 架空の店舗・商品・レシート・チラシを用意する。
- [x] OCR成功、誤認識、重複、期限切れ、容量違いを再現する。
- [x] developer専用の修正・確定画面を作る。
- [x] DBへ自動登録しない。
- [ ] 合成画像8枚以上でOCRベンチマークを実行し、フィールド別精度を保存する。
- [ ] Tesseract、Google Cloud Vision、Amazon Textractを同一画像で比較する。
- [ ] クラウド比較は専用テストプロジェクト、上限予算、画像即時削除を設定してから行う。

### 第1段階の終了条件

- 店舗、日時、商品名、価格の各正解率と1枚当たり処理時間を再現可能に計測できる。
- 誤認識を30秒以内に修正できるか、合成データで評価できる。
- 重複・容量違いを誤って同一観測へ確定しない。
- 本番ユーザー、家計簿、割引メモへ一切書き込まない。

## 第2段階: 正式リリース前の調整

開始条件: プライバシー文案、削除責任者、非公開Storage、処理用サーバー、監査方法がレビュー済み。

1. 家計簿登録と匿名相場提供の同意を分離し、相場提供は初期オフにする。
2. 未成年にも理解できる利用目的、保持期間、削除方法、同意撤回の説明を用意する。
3. 非公開Storage、本人・処理サーバー限定RLS、アップロード上限、画像マスクを実装する。
4. `service_role`はサーバー側Secretsだけに置き、ブラウザ・APK・リポジトリへ含めない。
5. 確定後の画像期限削除、解析結果削除、価格提供削除、バックアップ失効手順を実装する。
6. 個別商品を含めず、次のイベント名と処理時間・結果コードだけを計測する。
   - `receipt_upload_started`
   - `receipt_ocr_completed`
   - `receipt_corrected`
   - `receipt_confirmed`
   - `receipt_abandoned`
7. 本番では次のフラグをすべてオフとし、環境単位のサーバー設定でのみ変更する。
   - `price_intelligence_enabled`
   - `receipt_market_opt_in_enabled`
   - `store_flyer_import_enabled`
   - `store_social_import_enabled`

### 第2段階の終了条件

- 同意撤回から本体・Storage・派生観測・バックアップ失効まで追跡できる。
- アップロード前またはサーバー受信直後に会員番号、カード番号、決済番号をマスクできる。
- RLSの本人分離、店舗契約分離、管理者監査を自動テストできる。
- 既存の店舗ID、商品数量・単位、割引メモの出典・確認日時を移行試験できる。

## 第3段階: 導入決定後

### 開始ゲート

- 正式版の継続利用状況を確認済み。
- レシート提供同意率が事前基準を満たす。
- 協力店舗2〜3店を契約・許諾済み。
- OCR・Storage・運用費を12か月継続可能。
- プライバシーポリシーと利用規約を更新済み。

### 実施順序

1. 1地域、2〜3店舗、食品・日用品約100商品で限定パイロット。
2. アップロード、マスク、OCR、候補照合、確認、重複判定、観測登録、期限削除を接続。
3. 店舗手動登録を先行し、許可済みの公式API・OAuthだけを追加。
4. 数量・単位を正規化し、地域内・直近30〜90日の中央値を計算。
5. 出典数、観測数、最終確認日を必ず併記。データ不足時は「参考価格」とする。
6. 出典、新しさ、複数一致、ユーザー確認で信頼度を算出し、低信頼は確認待ちにする。
7. デバッグ、招待、地域、カテゴリ、全体の順に公開し、各段階でロールバック可能にする。

## 評価指標

- 店舗名、日時、商品、価格のフィールド別抽出精度
- JAN・商品名・容量・メーカーによる商品同一化精度
- ユーザー修正率、修正時間、途中離脱率
- 参考価格を表示可能な商品の割合、観測数、平均経過日数
- 参考価格確認後の買い物メモ追加率
- レシート提供継続率、店舗情報保存率、地図表示率
- 1枚当たりOCR費、画像保管費、問い合わせ件数、削除依頼完了時間

## 公開サイトを止めない運用

- 開発は機能ブランチで行い、一般ページへ導線を追加しない。
- DBマイグレーションは別PRとし、先にステージングでRLS・ロールバックを確認する。
- フラグがない、取得に失敗した、設定が不正な場合は必ずオフとして扱う。
- 既存のレシート入力・家計簿・割引メモと新しい取込処理を同時に置換しない。
- 一段階ずつ公開し、エラー率・費用・削除依頼が基準を超えたら直前段階へ戻す。
